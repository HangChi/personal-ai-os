### 裁判校验：一次明显低估与独立保留的复核

来源题 source-rta 的两个回答均给出了正确作者、原文链接和“索引卡并非全文”的收录范围。
主评测事实 F1 为 Java 0.80、Go 0.00。对这同一题做诊断性重评后，两端均为 0.80；
复核记录显示裁判有时把题目已提供、但简短参考答案未复述的文章标题，以及更具体的收录描述判成不受支持。
这说明默认英文拆解提示与中文简短参考之间存在明显噪声。复核并不能还原首次 0 分的全部内部判断，
也不应凭一次复核断言所有低分都是误判。

**主表仍保留首次有效的 0.00，没有拿较好的重评分替换；**复核只用于说明裁判局限，
完整分解和推断记录另存 factual-audit.json。后续应先用已知正确/错误样例校准裁判，
将参考答案写成包含题目主体的独立完整事实，再用独立模型或人工抽查。

主评测（含补重试）实际调用 689 次，记录 1,167,156 tokens，
其中输入 1,002,100、输出 165,056；诊断复核另调用 8 次、9,333 tokens。
端到端冒烟另有 17 次裁判调用、24,601 tokens。80 次业务问答的接口未提供模型 usage，
未把这些裁判 Token 冒充问答全链路用量，也未按未经核验的价格估算费用。


四项指标解释：

- **Faithfulness**：回答中的陈述是否得到返回上下文的支持。高分不代表问题已被回答。
- **Factual Correctness（F1）**：回答与参考答案的事实准确和覆盖程度。参考答案较短，
  正确但超出参考的补充内容、或回答未复述参考中的背景，都可能影响分数。
- **Context Precision**：RAGAS 基于参考答案判断返回证据的相关性及排序，
  不是本仓库旧脚本中的“标注文档数 / 5”。
- **Context Recall**：返回证据是否覆盖参考答案需要的事实，能够发现“文档命中但片段不对”。

评分使用官方 `ragas.metrics.collections` 实现、temperature 0、默认英文提示词处理中文输入。
34 道正例的保守拒答也纳入评分，不只保留成功答案。6 道负例不混入这四项平均分，
单独看拒答与逐条复核。缺少返回证据的正例，其上下文相关分数按 0 计并保留原因；
裁判异常不会默认为 0 或被隐藏，每项显示有效样本数。

| answer 阶段 FALLBACK | 2 次 | 0 次 |
| 端到端 P50，全部 40 题 | 7.164 秒 | 7.732 秒 |

| 端到端 P50 / P95，仅 34 道正例 | 7.237 / 13.108 秒 | 7.984 / 11.221 秒 |

**口径：** Hit@k 是前 k 个不同文档至少命中一个标注来源，不能称为完整来源 Recall@k。
“全部来源覆盖”另行要求所有标注文档都出现。这里评价的是 API 最终返回的证据列表，
不是内部原始召回候选；保护性返回有时保留超过 5 个分块，文档 Hit@k 仍严格截取前 k 个不同文档。
RAGAS 使用全部实际返回上下文。

answered 是接口状态，不等于语义正确率：Go 的 `idem-conflict` 为 true，但没有答出 409；
Java 的 `cross-unknown` 为 false，却给出了主要事实并附加了不必要的“分歧”。
引用一致性只校验编号集合和原分块哈希，不能证明引用足以支持结论。
P50 为中位数、P95 为 nearest-rank；单轮共享上游模型的延迟包含网络与模型波动，
不是语言运行时性能测试，也不是并发吞吐测试。

额外字面关键点诊断：Java 全覆盖 28/34，平均覆盖 85.3%；Go 全覆盖 30/34，平均覆盖 90.2%。
忽略大小写、空白和 Markdown 下划线转义，按同义词组匹配；详细匹配见 `keypoint-diagnostics.json`。
它仍会漏判等义表述，例如“提交**之后**”或未复述“草稿”一词，所以不作为最终正确率。
该文件由最新 `summarize` 从原始回答离线重算，优先于采集文件中的早期字面诊断值。

|---|---|---|---|

### 命中文档仍然漏掉答案

`scenario-idempotency.md` 第 12 行明确写着：

> 同一键携带不同商品数量必须返回 HTTP 409，不能悄悄复用不匹配的结果。

后续测试用例还多次重复这一依据。但 `idem-conflict` 中，Java 返回 2 个、Go 返回 3 个证据分块，
均不含“HTTP 409”。所以文档命中率为 100% 仍不能证明证据片段足以回答问题。
本例应首先排查分块级召回、排序和证据筛选，不宜只把检索 topK 调大或只看文档级指标。

### 互补信息被当成冲突

Java 的 `cross-unknown` 分歧理由自己写明“两者属于不同侧重，而非直接矛盾”，
但最终仍以 CONFLICT 呈现。订单资料要求“禁止重复扣减、先查询回执”，
MCP 资料要求“保留工具名、参数摘要、请求标识”，可以同时成立。
本例支持收紧冲突判定条件，不支持自动关闭所有冲突保护。

### 负例和安全边界

逐条复核 12 个负例回答，均未编造所问的密钥、客户、实验数字或未来政策。
严格状态拒答的唯一失分是 Java 的 `unknown-key`，不能把它描述成泄露密钥。
提示注入样例题两端均说明攻击句只是资料、DEMO-NOT-A-SECRET 是占位文本。
这仅验证本题表现，不构成全面提示注入安全认证。

## 5. 建议优先级

1. **补分块级证据回归。** 先固定 `idem-conflict`，要求返回证据包含 409，
   并追踪它在召回、重排、精审各阶段何时消失；同时保留现有文档级指标。
2. **收紧冲突判定。** 同主体、同版本、同适用范围、同事实字段且取值不能同时成立才判冲突；
   用 `mcp-retry` 和 `cross-unknown` 验证互补说明不再触发误报。
3. **提高精审可诊断性。** 为 UNVERIFIED / FALLBACK 记录不含秘密的原因码，
   区分超时、结构化输出解析、证据引用匹配等原因。本轮 trace 没有这些细分信息，
   不能把所有失败都归因于超时。
4. **统一 answered 与引用契约。** 纯缺资料回答应返回 false 和一致的状态；
   没有正文引用标记时不要额外返回一条貌似已引用的证据，回归 `unknown-key`。
5. **扩大验证后再决定迁移。** 增加真实正文与独立留出题，关键题重复至少 3 轮，
   并使用另一模型或人工复核。后续优化用同一快照、同一题集做配对对比，另设留出题避免过拟合。

本轮只添加评测脚本、题集和报告，没有修改 RAG 业务实现。

## 6. 限制与证据文件

- 80 份来源卡不是文章全文，不能用本轮结果声称原文细节问答能力已通过。
- 20 份场景为虚构数据，不能外推到真实生产配置、价格、吞吐或业务政策。
- 只测现有分块/索引快照；未重新执行 Java / Go 文档入库与切分，不代表两端入库质量一致。
- 每题每端一次，生成温度 0.7；同一上游模型自评，存在随机性、自评偏差及中英文提示适配偏差。

- 与仓库旧的“26 篇正文 / 129 题”评测不同，不能直接比较数字。
