## 3. 精度和召回的含义

本轮主指标不采用旧的固定P@5代表总体“准确率”，也不除以理论上限美化。前k名是排序观察窗口，是否选5必须与应用目标有关；一题只有一个已知支持文档时，已知来源P@5受金标稀疏影响，既不能证明其余文档都无关，也不能代表回答答对率。

- **选中证据精度**：逐题“已确认相关分块数 / 已完成相关或不相关判定的实际选中分块数”。`uncertain`与未判定不塞入分母；同时报告判定覆盖率、有效题数、宏平均和微平均，空上下文不记100%。
- **证据参考事实召回**：选中证据支持的冻结参考事实数 / 该题参考事实总数，不是全库穷尽相关文档召回。
- **回答事实精度**：回答中受证据支持且与问题相关的可核验事实数 / 生成事实数；可答题无事实拒答按0计。**回答参考事实召回**是回答覆盖的参考事实比例，F1逐题计算再平均，不由表中宏平均P/R反推。
- **引用支持精度**：有引用事实中，被其所指引用证据支持的比例，只在有引用事实样本上计算并列有效数。
- **RAGAS**：保留官方指标原值和零分。ContextPrecision在本地0.4.3实现中按相关块位置计算average precision，分母为相关判定数量，不是普通“相关块/全部块”比例；因此不能直接和上述证据精度互换。FactualCorrectness F1、AnswerRelevancy也不是人工答对率。

相关性判定池为原问题共享候选与生产最终证据的并集，没有保存生产改写后的完整候选池。池召回只对已判并集有效，不能称为生产全候选召回或全库真实召回。相邻来源可能有部分块确实支持问题，不能整个来源标负。块支持与回答覆盖分别审查，复合参考事实的边界可能产生分歧，不能对两个召回做精确因果相减。

## 7. 为什么低分：真实失分与裁判边界分别保留

**真实漏块例：technical-11（Vue const enum / Vite）。** 无重排的支持文档已排第1，但选入的是标题/引言，关键原因段未进入上下文，答案明确表示没有具体原因，RAGAS F1为0。每文档先一块与4块预算可能使同文档关键块被其他来源挤出。不是提高来源命中率就能解决，也不能把所有零分推给裁判。

**可确认的NLI边界例：hard-8 / rerank（Unitree G1 + LeRobot）。** 逐事实审查P/R均为1，RAGAS F1却为0。保存的NLI承认参考支持64维SONIC latent action tokens和PD controller，却因参考没重述回答里的来源编号、Unitree G1和LeRobot等完整对象，把回答侧两条主张全判0；反向参考事实被回答支持为1。这是本轮可直接核查的裁判边界问题，保留原始0分，没有另造“修正分数”。

**粒度差异：technical-16 / rerank、production。** 逐事实审查P/R为1，RAGAS F1仅0.27/0.24；参考指定Baize CLI 1.3.0，回答省略版本，反向NLI因缺版本判0。multi-2 / rerank的0.13则还涉及具体调度描述与泛化解释不一致，不能把所有分歧统称误判。
