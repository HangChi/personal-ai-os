# 记忆、上下文与模型选择

项目把“数据库保存的历史”和“本次发给模型的内容”分开处理。历史存在不代表每次都全量发送；上下文裁剪也不意味着删除历史。本文适用于两版共享设计，具体边界见[双版本说明](backend-parity.md)。

## 1. 四种内容

| 层 | 数据与用途 | 生命周期 |
| --- | --- | --- |
| 原始会话历史 | 用户/助手消息、引用、附件关联 | 追加保存，分页读取 |
| 滚动摘要 | 会话早期上下文的有界摘要与序号进度 | 会话内持久化，不替代原文 |
| 长期记忆 | 偏好、稳定事实、用户明确要求记住的信息 | 跨会话，支持管理、置顶、取代和删除 |
| 本轮证据 | 知识/网页检索片段和工具回执 | 本轮注入，引用快照可持久保存 |

摘要与长期记忆不是知识库文档，也不是对事实正确性的保证。知识库按问题检索证据；记忆按约束与预算注入，两者不能混用去重/排序策略。

## 2. 系统提示与预算

Java `ChatPromptAssembler` / Go `chat/prompt.go` 拼装人设、摘要、模块贡献、附件与知识片段，历史由记忆窗口单独提供。模块贡献包含当前时间/时区、长期记忆、计划和确认状态；系统时间每轮刷新，用于解释“明天”等相对时间。

预算检查覆盖**完整模型请求**：系统提示、当前输入、历史、附件、图片预留、工具 JSON Schema 和工具往返。UI 的“输入预算”“模型上限”“已用 token”分别展示，估算值带来源；默认预算不是端点最大能力声明。

| 配置 | 默认 | 作用 |
| --- | --- | --- |
| `AI_MEMORY_MAX_MESSAGES` | 20 | 近期消息窗口上限 |
| `AI_MEMORY_MAX_CONTEXT_CHARS` | 12000 | 近期历史字符预算 |
| `CONTEXT_OUTPUT_RESERVE_TOKENS` | 4096 | 回复预留 |
| `CONTEXT_SAFETY_MARGIN_TOKENS` | 512 | 安全余量 |
| `CONTEXT_IMAGE_RESERVE_TOKENS` | 4096 | 图片保守预留 |
| `CONTEXT_MAX_RETRIES` | 1 | 明确上下文超限且未输出时的缩减重试，支持 0–2 |

保护层优先移出最早的完整轮次，避免拆散工具调用与返回。过大工具结果可带标识地截断；当前用户输入和附件不会静默截断，仍放不下则明确报错。深度思考还预留思考 token，能容纳的输入相应减少。

只有端点明确报告上下文超限、且该次模型请求尚未输出块时，才按预算缩减重试；不重做已执行工具、不重复保存用户消息。已输出或重试仍失败则终止，不无限重试。

## 3. 滚动摘要

默认开启，至少新增 4 条消息才处理；每批原文最多 4000 字符，摘要最多 1200 字符。摘要覆盖进度与内容一起保存，后续只处理尚未摘要的片段。临近预算时可在发送前最多推进两个批次，轮末也有后台维护；失败保留旧摘要和原文。

摘要客户端没有业务工具权限，不能把“旧对话中的指令”当新工具执行请求。摘要有损，重要信息仍应通过原消息/明确记忆核对，不能用“模型记住了”代替数据查询。

## 4. 长期记忆选择

手动记忆和 `saveMemory` 经过统一服务。单条最多 2000 字符；自动沉淀默认关闭，开启 `AI_CONTEXT_AUTO_MEMORY_ENABLED=true` 后每轮最多抽取 3 条候选稳定事实，会额外调用模型。

注入读取最近 120 条未被取代的候选，先置顶，再对普通条目排序，最多 30 条、内容总计 6000 字符；达到预算整条停止，不切半条约束。置顶默认最多 10 条，仍受候选与总预算约束，不是无限上下文保证。

普通条目评分：

```text
score = 0.7 × relevance + 0.3 × recency
recency = 0.5 ^ (距最近更新时间天数 / halfLifeDays)
默认 halfLifeDays=30
```

相关度优先使用同模型记忆向量余弦（归一到 0–1），缺失/超时时用中文英文字符二元组重叠；无可用输入时新近度成为主要排序依据。查询嵌入只取最多 200 字符，默认超时 400ms。排序只决定预算内先放谁，不是“未命中检索就永远不注入”。

近重复向量阈值默认 0.92；相似旧条目标为 `supersededBy`，保留可追溯记录，不物理删除；旧置顶意图转移到新条目。嵌入不可用不应让显式记忆丢失，后续回填按配置执行。记忆变更需要在界面核对，自动提炼可能把一次性说法误当长期偏好。

## 5. 模型配置、窗口来源与被动校准

聊天/嵌入协议支持 Ollama 与 OpenAI 兼容端点。数据库模型档案、环境默认值、会话选模型共同决定实际请求，不能只看 `.env` 判断当前模型。

Java 原子替换模型/客户端组合，已有流持有原组合完成；Go 按自身 Runtime/配置代数解析。具名模型继承有效配置的端点、凭据与参数，不通过修改全局模型实现会话选择。知识问答、摘要、视觉转录等使用相应无工具客户端。

窗口可来自手填、端点探测或内置参考，UI 标明来源；无法识别时使用保护预算并显示未知。参考值不是对当前代理端点的实测认证。

正常请求被动积累窗口证据：明确的超限声明收紧输入上限，真实 usage 校正偏低估算，成功请求只证明已接受的输入下限。切换/重新应用模型配置或重启会清除对应证据，不额外发送大段探测文本消耗额度；旧请求不能污染新配置代数。

## 6. 排查顺序与源码

“忘记历史”先确认历史是否落库，再看摘要进度、近期窗口、固定开销、实际模型窗口与裁剪；不要一开始就调高消息数。“重复记忆”检查规范化哈希、嵌入模型标记及取代关系。“token 看起来突然变大”先比较真实/估算来源与工具 Schema 开销。
