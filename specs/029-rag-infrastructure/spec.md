# 基础设施扩展与可信混合 RAG

用户要求逐项实现 Redis、消息队列、独立检索与 S3，以及查询改写、多路召回、重排精排和资料冲突处理。

- PostgreSQL 保持事实来源。Redis 仅缓存可再生嵌入；RabbitMQ 只通知数据库任务，不携带文件，不承诺外部副作用 exactly-once。
- OpenSearch 为可重建的关键词/BM25 和 kNN 投影。删除、替换、导入也必须同步；返回前用 PostgreSQL 校验片段仍存在。
- S3 兼容对象存储用于附件，默认保留本地存储兼容，不静默迁移或删除已有文件。
- 原查询始终保留，改写有次数、长度、超时边界。召回融合后才重排和精排，降级必须可观察。
- 真实 cross-encoder 重排可通过兼容 API 接入；使用已有无工具模型提供受限 listwise 重排及证据精审。
- 知识空间、来源版本、适用范围、有效时间、人工设定可信级别必须保留。不同范围/时间不直接判为矛盾。
- 入库审查提取有原文证据的候选事实，保留冲突、审查覆盖状态和人工决策；不自动覆盖资料或按上传时间判真伪。
- 同范围矛盾和模糊问题不输出无条件的单一结论。并列来源、请求澄清；所有引用由服务端绑定实际片段。
- 默认不开启新增外部服务；明确配置后才连接。服务故障有超时与降级，原有同步/API 契约兼容。
- 分阶段测试、提交；隔离工作区构建，避免覆盖运行中的 JAR。
