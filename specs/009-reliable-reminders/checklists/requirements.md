## 可判定性

| FR | 判定方式 |
|---|---|
| FR-001 系统通知 | stub `Notification`，断言构造次数与参数 |
| FR-002 可见时用站内 | 同上，断言 0 次构造 + 站内 DOM 出现 |
| FR-003 会话内去重 | 同一 id 三次 → 构造 1 次 |
| FR-004 汇总 | 4 条 → 1 次，标题含数量 |
| FR-005 点击聚焦 | 浏览器实测：点击后 `document.visibilityState`/焦点变化；导航到 /calendar |
| FR-006 只在手势内请求 | 进入页面后断言 `requestPermission` 未被调用（stub 计数器） |
| FR-007 denied 不再请求 | denied 状态下点击路径不存在 + stub 计数为 0 |
| FR-008 降级不退化 | default/denied 下徽标与列表仍渲染 |
| FR-009 不支持 | 删除 `window.Notification` 后显示文案、无按钮 |
| FR-010 构造失败不中断 | 注入抛错的 `notify` → 后续轮询仍执行 |

> FR-005 的「点击通知」在自动化里较难触发（浏览器不派发该事件给页面）。
> 实现上它只是 `notification.onclick = () => {...}`，验收时标 ⏳ 并说明"只验证了赋值存在"。

## 与宪法的对齐

| 条款 | 满足方式 |
|---|---|
| I 简单优先 | 零依赖、无 Service Worker、去重不持久化 |
| II 边界即安全 | 只读提醒，不写数据；权限请求不劫持用户 |
| III 分层收敛 | 通知逻辑独立模块，视图只渲染状态 |
| IV 数据可追溯 | 无 DB 变更 |
| V 可验证 | 核心分支是纯函数；通知调用经注入函数，可断言 |
