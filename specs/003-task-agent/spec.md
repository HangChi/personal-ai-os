# Feature Specification: 阶段 2 — 任务管理与 Agent 工具调用

**Feature Branch**: `003-task-agent`

**Created**: 2026-10-14

**Status**: Draft

**Input**: 用户需求：「实现任务管理 Agent。先实现任务创建、查询、修改、完成和删除，再使用 Spring AI `@Tool` 将这些功能提供给 Agent。支持自然语言操作任务。需要参数校验、工具执行日志、重复请求处理，并对删除等高风险操作进行人工确认。确保 Agent 调用后数据库真正发生预期变化，并提供集成测试。」

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用自然语言管理任务（Priority: P1）

作为用户，我希望在对话里直接说「帮我加一个任务：周五前把周报写完」，助手就真的把任务建好，而不是只回一句「好的」。

**Why this priority**：这是本阶段的核心价值 —— 把「对话」变成「操作」。

**Independent Test**：在对话中发送一条建任务的自然语言指令，随后查询任务列表，能看到该任务。

**Acceptance Scenarios**：

1. **Given** 任务库为空，**When** 在对话中说「加一个任务：明天交周报」，**Then** 任务库中出现标题包含「交周报」的任务，且对话回复告知已创建。
2. **Given** 已存在若干任务，**When** 问「我有哪些待办」，**Then** 回复列出未完成任务的标题。
3. **Given** 存在任务「交周报」，**When** 说「把交周报标记完成」，**Then** 该任务状态变为已完成且记录完成时间。
4. **Given** 任务标题含特殊字符或超长，**When** 通过对话创建，**Then** 工具拒绝并返回可读原因，且**不产生任何数据库写入**。

---

### User Story 2 - 高风险操作需人工确认（Priority: P1）

作为用户，我不希望助手「自作主张」删掉我的任务。删除、批量操作、修改关键字段都必须先经我确认。

**Why this priority**：一旦失守就是**不可逆的数据丢失**。这属于正确性与安全边界，不是体验优化。

**Independent Test**：让助手执行删除，观察任务**仍然存在**且系统产生一条待确认记录；再让助手自行尝试「确认」，观察它**没有任何可用途径**完成删除。

**Acceptance Scenarios**：

1. **Given** 存在一个任务，**When** 助手请求删除它，**Then** 任务仍然存在，系统返回「需要确认」并生成一条待确认记录。
2. **Given** 已生成待确认记录，**When** 人类用户在界面上确认，**Then** 任务被真正删除，记录状态变为已确认。
3. **Given** 已生成待确认记录，**When** 人类用户取消，**Then** 任务不受影响，记录状态变为已取消。
4. **Given** 已生成待确认记录，**When** 超过有效期后再确认，**Then** 拒绝执行并提示已过期。
5. **Given** 已确认执行过一次，**When** 用同一记录再次确认，**Then** 拒绝重复执行（单次性）。
6. **Given** 模型能调用的工具集合，**When** 检查该集合，**Then** **不存在任何**可以完成「确认」动作的工具 —— 模型无法绕过人类。

---

### User Story 3 - 重复请求不会造成重复副作用（Priority: P1）

作为用户，我不希望因为模型重复调用或网络重试，导致同一个任务被建了两遍、或删了两遍。

**Why this priority**：重复写入是「静默的数据污染」，用户往往很久之后才发现。

**Independent Test**：用同一幂等键重复发起同一写操作，检查数据库中该资源只存在一份，且第二次返回与第一次一致。

**Acceptance Scenarios**：

1. **Given** 同一次对话轮次内，**When** 模型对同一操作、同一参数重复调用工具，**Then** 只有第一次真正执行，第二次返回与第一次相同的结果。
2. **Given** 携带同一幂等键，**When** 客户端重复发起同一个创建请求，**Then** 只创建一个任务，且两次响应一致。
3. **Given** 携带同一幂等键但**参数不同**，**When** 发起请求，**Then** 返回冲突错误，而不是静默执行成另一件事。
4. **Given** 不同对话轮次中的相同操作，**When** 分别执行，**Then** **都**真实执行（跨轮次不视为重复）。

---

### User Story 4 - 任务 REST 管理（Priority: P2）

作为用户，我希望在任务页面上直接管理任务（新建、筛选、完成、删除），不必每次都通过对话。

**Why this priority**：图形界面是确定性操作的入口；但没有它，对话路径已可用。

**Independent Test**：在任务页面完成一次新建 → 筛选 → 完成 → 删除的完整流程。

**Acceptance Scenarios**：

1. **Given** 任务页，**When** 新建任务，**Then** 列表出现该任务。
2. **Given** 多个任务，**When** 按状态筛选，**Then** 只显示匹配项。
3. **Given** 存在任务，**When** 直接删除（人工操作），**Then** 立即删除且无需确认 —— 因为发起者就是人本身。
4. **Given** 指定不存在的任务，**When** 修改或删除，**Then** 返回明确的「资源不存在」。

---

### User Story 5 - 工具执行可审计（Priority: P2）

作为自托管用户，我希望知道助手到底替我做了什么，以及每次工具调用的参数与结果。

**Why this priority**：Agent 的副作用不可见就无法信任；但它是可观测性增强，不阻塞核心链路。

**Independent Test**：让助手执行若干次工具调用，查询调用日志，能看到工具名、参数摘要、结果与耗时。

**Acceptance Scenarios**：

1. **Given** 助手执行了一次工具调用，**When** 查询调用日志，**Then** 存在一条记录，含工具名、结果状态与耗时。
2. **Given** 工具执行失败，**When** 查询日志，**Then** 该记录标记为失败并保留可读原因。
3. **Given** 某次工具调用因幂等被去重，**When** 查询日志，**Then** 该次调用被标记为「重复」，不与真实执行混淆。

---

### Edge Cases

- **模型传错任务标识**：不存在的任务 id 必须返回可读错误，而不是 500。
- **模型一次传过多 id**：批量删除超过上限（50）时拒绝并提示拆分。
- **关键字段取值范围**：优先级只接受枚举值；截止时间必须可被解析；非法值不得写入。
- **确认记录并发确认**：两个请求同时确认同一条记录时，只允许一个成功。
- **工具执行中途失败**：不得留下「部分成功」的假象（批量删除要么全删要么不删）。
- **幂等键超长或含非法字符**：在边界处拒绝。
- **确认时目标已被删除**：提示「目标已不存在」，记录标记为已取消，不得报 500。
- **空关键词查询**：返回最近的任务而不是报错。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：系统 MUST 提供任务的创建、查询（列表与单个）、修改、标记完成/取消完成、删除能力。
- **FR-002**：任务 MUST 至少包含：标题、描述、状态、优先级、截止时间、创建时间、更新时间、完成时间。
- **FR-003**：状态取值 MUST 限定为待办/进行中/已完成；优先级 MUST 限定为低/中/高。
- **FR-004**：系统 MUST 以 Spring AI 工具的形式，把任务能力暴露给模型。
- **FR-005**：模型 MUST NOT 直接访问数据库；所有副作用 MUST 经过显式定义的 Java 工具方法。
- **FR-006**：所有工具入参 MUST 在边界校验（必填、长度、枚举、数量上限）；非法入参 MUST 返回可读错误且**不产生任何写入**。
- **FR-007**：删除任务 MUST 经人工确认才真正执行；模型只能**申请**删除。
- **FR-008**：修改截止时间与优先级 MUST 经人工确认；修改标题/描述与标记完成 MUST NOT 需要确认（可逆、非破坏）。
- **FR-009**：一次影响多于一行的批量操作 MUST 经人工确认。
- **FR-010**：确认信息 MUST 绑定到具体的操作与参数，并向人类展示「将要发生的动作」的可读描述。
- **FR-011**：确认 MUST 具备有效期且只能使用一次。
- **FR-012**：确认令牌 MUST NOT 下发给模型；完成确认的途径 MUST 只存在于面向人类的接口中。
- **FR-013**：模型可调用的工具集合中 MUST NOT 包含任何「确认」类工具。
- **FR-014**：同一对话轮次内，同一工具 + 同一参数重复调用 MUST 只执行一次，并返回首次结果。
- **FR-015**：携带相同幂等键的重复 HTTP 写请求 MUST 只执行一次，并返回与首次一致的响应。
- **FR-016**：相同幂等键但请求内容不同时，MUST 返回冲突错误。
- **FR-017**：每次工具调用 MUST 留下可审计日志，含：工具名、参数摘要、结果状态、耗时、所属会话。
- **FR-018**：因幂等被去重的调用 MUST 在日志中与真实执行区分开。
- **FR-019**：所有新接口 MUST 使用既有统一响应结构；错误码遵守既有契约。
- **FR-020**：MUST NOT 向前端暴露 JPA 实体；对外一律 DTO。
- **FR-021**：所有写操作 MUST 经过 Service 层。
- **FR-022**：数据库结构变更 MUST 由 Flyway 迁移管理。
- **FR-023**：任务列表查询 MUST 支持按状态筛选与关键词匹配，并 MUST 限制返回条数。
- **FR-024**：人工通过 REST 直接删除任务 MUST NOT 需要确认（发起者即人类）。

**范围边界（本阶段明确不含）**：

- 不含知识库与 RAG（阶段 3）。
- 不含日程与提醒（阶段 4）——任务上的截止时间**不会**触发任何通知。
- 不含子任务、标签、任务间依赖、重复任务（循环任务）。
- 不含多人协作、任务指派、评论。
- 不含 MCP 集成。
- 不含对模型输出的结构化约束（如强制 JSON），仍为自然语言 + 工具结果。
- 不含确认的推送通知（需用户主动刷新待确认列表）。

### Key Entities

- **Task（任务）**：标题、描述、状态、优先级、截止时间、完成时间、创建/更新时间。
- **TaskConfirmation（待确认操作）**：动作类型、面向人类的可读描述、执行所需参数、令牌、状态、有效期。
- **OperationRecord（操作记录）**：用于工具执行审计与两层幂等；含幂等键、来源、操作名、参数摘要、结果状态、耗时。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：助手收到建任务指令后，任务在**同一轮对话结束前**即出现在数据库中（集成测试断言库变化）。
- **SC-002**：需确认的操作在未确认前，目标数据的**变化行数为 0**；确认后变化行数为预期值。
- **SC-003**：模型可调用的工具中，可完成「确认」动作的工具数量为 **0**。
- **SC-004**：同一轮次内重复调用同一工具，数据库受影响行数为首次的 **1 倍**（不翻倍）。
- **SC-005**：携带同一幂等键的重复请求，创建出的资源数为 **1**。
- **SC-006**：非法入参（空标题、超长标题、非法优先级、超量批量）导致的数据库写入行数为 **0**。
- **SC-007**：每次工具调用都有对应日志记录（日志条数 == 调用次数，含被去重与失败的调用）。
- **SC-008**：过期或已使用的确认执行失败率为 **100%**。
- **SC-009**：新增集成测试在无外部网络、无 API 密钥下全部通过（桩模型驱动工具调用）。

## Assumptions

- 阶段 2 仍为**本地单用户**，因此任务不绑定用户；「人工确认」的「人」即本机使用者。
- 确认的有效期默认 **10 分钟**；过期记录在查询时标记为已过期，不做后台清理。
- 工具层幂等的范围是**单次对话轮次**（由轮次标识界定），跨轮次的相同操作视为用户的有意重复。
- HTTP 幂等键由客户端提供（请求头）；未提供时不启用 HTTP 层幂等，行为与普通请求一致。
- 批量操作上限 **50** 条；超出提示拆分，而不是静默截断。
- 助手在对话中**不会**代用户确认；确认必须由人在界面上完成。
