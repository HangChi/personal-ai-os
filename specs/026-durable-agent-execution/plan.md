# 实现设计

保持 Spring MVC、Spring AI、PostgreSQL、Vue/Pinia 技术栈，无新增运行时依赖。

`chat_run` 保存原始请求与执行状态，`chat_run_event` 保存递增事件；Flyway V32 追加结构。后台使用 RunEmitter 输出到持久化事件，不绑定网络连接。原 SSE 接口兼容保留；新版界面每 300ms 增量追赶事件，每批上限 200 条，断线仅重试只读接口并退避至 5 秒。

ToolExecutor 经 ToolProgress 发布真实开始与结束事件，不外发参数、原始结果或隐藏思考。续跑沿用 run id 作为 turn id，历史工具回执注入恢复上下文，控制工具 startPlanStep 允许再次转移状态。结果未知的工具占位不再因时间过期而被删除重做。

单实例启动时恢复原 RUNNING 记录；存在待人工确认或未决工具记录时保留中断状态。使用原有人工确认 API 与服务端生成的摘要，不扩张模型权限。旧确认回执由现有 ConfirmationPromptContributor 注入最新状态。

界面沿用项目语义色、字体和圆角，以展开的工具活动列表显示当前阶段、工具名、成败和耗时。确认采用类似问答的内联授权卡片，单次点击直接传递决定；暂不选择保留待确认，操作过期与执行错误就地显示。

取舍：恢复单位是工具调用和计划步骤，不保存任意外部进程的内部执行位置。外部写操作在崩溃窗口结果不明时必须核查，不能宣称通用 exactly-once。执行和幂等记录需要保留至任务不再恢复；清理历史审计后不应再续跑旧任务。新消息有新的执行身份，合法的同名操作不会被全会话去重。
