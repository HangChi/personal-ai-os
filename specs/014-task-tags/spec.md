# Feature Specification: 阶段 14 — 任务标签

**Feature Branch**: `014-task-tags`

**Created**: 2026-10-25

**Status**: Draft

**Input**: 用户需求：「继续剩余的内容」—— 任务只有标题/描述/状态/优先级，无法按清单或主题归类。

## 背景

任务模型有四个维度（状态、优先级、截止时间、描述），但没有「属于哪一类」。
实际使用中「工作 / 学习 / 家里」这类横向分类与优先级正交：
优先级回答「先做哪个」，标签回答「这是哪摊事」。

没有标签时用户只能用标题前缀（「[工作] 写周报」）凑合，代价是标题搜索被污染、
且无法可靠筛选。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 给任务打标签（Priority: P1）

作为用户，我在新建或编辑任务时能输入若干标签，列表里能看到它们。

**Why this priority**：没有它，其余两条（筛选、标签清单）都无从谈起。

**Independent Test**：新建一个带两个标签的任务 → 列表与详情都显示这两个标签；
编辑成三个 → 列表跟着变；清空 → 标签消失。

**Acceptance Scenarios**：

1. **Given** 新建任务时填 `工作`、`本周`，**When** 保存，**Then** 任务带这两个标签，且顺序与输入一致。
2. **Given** 已有任务带 `工作`，**When** 编辑为 `工作`、`学习`，**Then** 标签整体替换为这两个（不是追加）。
3. **Given** 编辑时把标签清空，**When** 保存，**Then** 该任务无标签（**不是**「没改动」）。
4. **Given** 输入 `工作`、`工作`、` 工作 `，**When** 保存，**Then** 只存一个 `工作`（去空白后去重）。
5. **Given** 输入 6 个标签，**When** 保存，**Then** 明确报错「最多 5 个标签」，不静默截断。

---

### User Story 2 - 按标签筛选（Priority: P1）

作为用户，我在任务列表上方选择一个标签，只看该标签的任务。

**Independent Test**：造两个不同标签的任务，选其中一个标签，列表只剩对应任务，`total` 同步。

**Acceptance Scenarios**：

1. **Given** 任务分布在不同标签，**When** 选择某标签，**Then** 只返回含该标签的任务。
2. **Given** 已按标签筛选，**When** 清空筛选，**Then** 回到全部任务。
3. **Given** 标签名含中文与空格，**When** 筛选，**Then** 精确匹配（不做模糊）。

---

### User Story 3 - 知道有哪些标签（Priority: P2）

作为用户，筛选下拉里应该列出我实际用过的标签，而不是让我凭记忆手输。

**Independent Test**：造几个带标签的任务，调标签清单接口，返回去重且排序的标签。

**Acceptance Scenarios**：

1. **Given** 库里标签为 `工作`、`学习`、`工作`，**When** 取清单，**Then** 返回 `[学习, 工作]`（去重且有序）。
2. **Given** 没有任何标签，**When** 取清单，**Then** 返回空数组（不是 404）。
3. **Given** 某任务被删除，**When** 取清单，**Then** 它的独有标签不再出现（无孤儿）。

## Edge Cases

| 输入 | 期望行为 |
|---|---|
| 标签为纯空白或空串 | 忽略该标签，不报错 |
| 标签超过 20 字符 | `40000`，提示长度上限 |
| 标签数超过 5 个 | `40000`，提示数量上限 |
| 标签含逗号 | 允许（存储是独立行，不做分隔符解析） |
| 删除任务 | 其标签行一并删除（外键级联），不留孤儿 |
| 同一任务同一标签重复 | 主键/去重保证只存一条 |
| 更新时只改标题不传 tags | 标签保持不变（null = 未提供） |

## Requirements *(mandatory)*

- **FR-001**：任务 MUST 支持 0–5 个标签，每个标签去空白后 1–20 字符。
- **FR-002**：标签 MUST 去重，且保留**首次出现的顺序**（列表展示与导出需要稳定顺序）。
- **FR-003**：创建/更新时标签 MUST 经过统一归一化（去空白 → 去空 → 去重 → 校验上限）。
- **FR-004**：更新语义 MUST 区分「未提供」（保持不变）与「空数组」（清空）。
- **FR-005**：任务列表 MUST 支持按标签精确筛选，`total` MUST 反映筛选后的数量。
- **FR-006**：MUST 提供去重且有序的标签清单接口，且不返回孤儿标签。
- **FR-007**：删除任务 MUST 级联删除其标签行。
- **FR-008**：导出 MUST 包含任务的标签（否则备份不完整）。
- **FR-009**：Agent 的 `createTask` MUST 支持 `tags` 参数；`findTasks` MUST 支持按标签筛选
  —— 否则「用自然语言管理带标签的任务」这个能力只对网页端有效。
- **FR-010**：本阶段 MUST NOT 做标签管理页（重命名、合并、批量改色）—— 那是独立的维护功能。

## Success Criteria

- **SC-001**：`./mvnw -B verify` 全绿；新增测试覆盖归一化（去空白/去重/超限）、
  整体替换与清空、按标签筛选、标签清单去重、删除级联。
- **SC-002**：`npm run test:logic` 全绿，覆盖「标签替换语义」在前端的表现（提交时传空数组）。
- **SC-003**：真机：新建带标签任务 → 列表显示 → 按标签筛选 → 清空筛选 → 编辑清空标签。

## Assumptions

- 标签是**自由文本**，不引入「标签库」预定义表：个人使用下，预定义流程（先进设置页建标签、
  再到任务里选）比直接输入多两步，而错别字带来的麻烦远小于这两步的摩擦。
- 标签不做颜色：颜色需要一张配置表或一列存储，而首版用 Element Plus 的默认 tag 样式
  已经能区分「有标签/没标签」这个主要信息。
- 标签不参与排序与统计：本阶段只解决「归类 + 筛选」，不做「每个标签多少任务」的报表。
