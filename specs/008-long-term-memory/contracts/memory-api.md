# Contract: 长期记忆（REST / 注入 / 工具）

**Date**: 2026-10-25 | **Spec**: [spec.md](../spec.md) | **Data**: [data-model.md](../data-model.md)

## 一、REST 接口

前缀 `/api/v1/memories`。本地单用户，无鉴权。所有响应走统一信封。

### 1. 列表

```
GET /api/v1/memories
```

`200` → `data` 为数组，按 `updated_at` 倒序，**不受注入预算影响**（返回全部）：

```json
{ "code": 0, "data": [
  { "id": "…", "content": "周报每周五下午交", "createdAt": "…", "updatedAt": "…" }
] }
```

无记忆 → `data: []`（不是 404，不是 null）。

### 2. 新增

```
POST /api/v1/memories
{ "content": "周报每周五下午交" }
```

`200` → 返回落库后的完整视图。

**去重**：`content` 归一后与已有条目完全相同时，**不新增**，返回既有条目（幂等，HTTP 仍 200）。

### 3. 编辑

```
PATCH /api/v1/memories/{id}
{ "content": "周报每周五上午交" }
```

`200` → 返回更新后的视图（`updatedAt` 刷新，`createdAt` 不变）。

### 4. 删除

```
DELETE /api/v1/memories/{id}
```

`200` → `data: null`。幂等性：删除后再删同一条 → `404`（与「删除会话」行为一致）。

### 错误响应

| HTTP | code | message | 条件 |
|---|---|---|---|
| 400 | 40000 | 记忆内容不能为空 | 归一后为空 |
| 400 | 40000 | 记忆内容长度不能超过 2000 | 归一后 > 2000 |
| 400 | 40000 | 记忆标识格式非法 | `id` 不匹配 `[A-Za-z0-9-]{1,64}`，**查库前**拒绝 |
| 404 | 40004 | 记忆不存在：{id} | 编辑/删除不存在的条目 |

### 判定顺序（顺序即契约）

1. 路径 `id` 格式 → 400
2. `content` 归一 + 非空 + 长度 → 400
3. 存在性（编辑/删除）→ 404
4. 写入

空内容必须在**查库之前**被拒（同 007 的理由：不让参数错误的成本取决于库状态）。

## 二、注入契约（送进模型系统提示的格式）

**触发**：仅会话内对话（`POST /chat/sessions/{id}/stream`）。知识库问答**不注入**（FR-007）。

**组装顺序**：

```
基础系统提示（AiProperties.systemPrompt()）
<空行>
记忆块（仅当记忆非空）
```

记忆块格式（**逐字契约**，测试据此断言）：

```
## 长期记忆

以下是用户明确要求你长期记住的信息，在所有回答中都应遵守：

1. 周报每周五下午交
2. 我常住扬州
```

| 规则 | 值 |
|---|---|
| 条数上限 | 30 |
| 累计字符上限 | 6000（只算条目正文，不含标题与编号） |
| 排序 | `updated_at` 倒序（最近的在前，编号从 1 开始） |
| 超预算 | 停止累加，**不截断单条**（R-05） |
| 记忆为空 | 整块不出现（含标题、空行都不出现） |

**为什么标题用二级标题 + 固定引导句**：模型对「以下是用户明确要求你记住的信息」这类显式指令
响应更稳定；同时让人在日志里一眼看出这段不是用户输入，而是系统注入。

## 三、Agent 工具契约

### `saveMemory`

| 项 | 约定 |
|---|---|
| 工具名 | `saveMemory` |
| 参数 | `content`（必填，字符串） |
| 描述要求 | 必须写明「**仅当用户明确要求长期记住某件事时调用**；不要自动记录对话内容」 |
| 成功返回 | 面向模型的一句话：「已记住：{content}」或「这条我已记过：{content}」（去重命中时） |
| 失败返回 | 校验失败的明确文案（模型据此转述给用户） |
| 确认 | **不需要**（R-07） |
| 幂等 | 同一轮重复调用同内容 → 只有一行（工具层幂等 + Service 去重双保险） |

### 不提供的工具

`deleteMemory` / `updateMemory` **不暴露给模型**。理由：破坏性操作只允许人在界面上发起
（宪法原则 II 的延伸：模型能影响后续所有对话，不能同时拥有删除权）。

## 四、前端契约

| 关注点 | 契约 |
|---|---|
| 页面 | `/memory`，导航标题「记忆」 |
| 列表 | 倒序展示，每条显示内容 + 更新时间（本地化格式） |
| 新增 | 文本域 + 保存；保存后刷新列表（新增会改变集合，必须重拉） |
| 编辑 | 就地或对话框编辑，成功后**就地替换**该项 |
| 删除 | 二次确认（不可撤销），成功后从本地列表移除 |
| 空状态 | `el-empty`「还没有长期记忆」+ 一句说明（在对话里说「记住…」也会出现在这里） |
| 校验 | 提交前：trim 后非空、≤ 2000；与后端同口径 |
| 错误 | 统一取自 `error` 字段，不吞掉 |

## 五、行为用例表

| # | Given | When | Then |
|---|---|---|---|
| M-1 | 无记忆 | GET 列表 | 200，`data: []` |
| M-2 | 无记忆 | 发起对话 | SystemMessage 与阶段 1 逐字符相同（无记忆块） |
| M-3 | 空库 | POST `{"content":"  周报周五交  "}` | 200，`content` 落库为「周报周五交」 |
| M-4 | 已有「周报周五交」 | POST 同内容（带首尾空格） | 200，返回既有条目，表仍 1 行 |
| M-5 | 1 条记忆 | 发起对话 | SystemMessage 含「## 长期记忆」与该条原文 |
| M-6 | 1 条记忆 | PATCH 改内容 | 200；下一轮对话 SystemMessage 含新内容、不含旧内容 |
| M-7 | 1 条记忆 | DELETE | 200；列表为空；下一轮对话无记忆块 |
| M-8 | 35 条记忆 | 发起对话 | 记忆块恰好 30 条，且为 `updated_at` 最近的 30 条 |
| M-9 | 记忆总字符 > 6000 | 发起对话 | 按倒序累加至超预算即停；不含被截断的半条 |
| M-10 | — | POST `{"content":"   "}` | 400/40000，表零写入 |
| M-11 | — | POST 2001 字符 | 400/40000 |
| M-12 | 记忆存在 | PATCH/DELETE 不存在 id | 404/40004 |
| M-13 | — | PATCH `bad_id_x` | 400/40000，**零查库** |
| M-14 | 桩模型被要求保存 | 对话中触发 `saveMemory` | 表新增 1 行；工具返回含「已记住」；回复告知用户 |
| M-15 | 知识库问答 | 发起 `/knowledge/ask` | 送给模型的 prompt **不含**「## 长期记忆」 |
