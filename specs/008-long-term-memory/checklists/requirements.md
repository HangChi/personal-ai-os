# Requirements Checklist: 阶段 8 — 长期记忆

**Purpose**: 实现前确认规格「写清楚了、可判定、无内部矛盾」。
**Created**: 2026-10-25 | **Spec**: [spec.md](../spec.md)

## 内容质量

- [x] 用户故事有独立价值：US-1 是「跨会话记住」，US-2 是「可见可改」；后者即使缺失，前者的注入价值仍成立
- [x] 优先级有依据：US-1 是功能本体（P1）；US-2 是可信度前提（P2）
- [x] 边界单独列出：空/超长/重复/超预算/不存在/非法 id/随口说记一下/连续多条/知识库链路，共 10 条
- [x] 「明确不含」6 项均给依据，且每项都能对应到 research 的一条决策

## Requirement 可判定性

| FR | 判定方式 |
|---|---|
| FR-001 工具存在且描述含约束 | 断言工具回调集合里有 `saveMemory`，且描述包含「明确要求」字样 |
| FR-002 回复告知 | 断言工具返回文案含「已记住」，且桩模型的下一轮上下文含该结果 |
| FR-003 归一 + 上限 | 输入带空格 → 落库无空格；2001 → 400 |
| FR-004 去重 | 同内容 3 次 → 表 1 行 |
| FR-005 注入存在性 | 桩模型 SystemMessage 断言 |
| FR-006 预算 | 35 条 → 恰好 30 条；超 6000 字符 → 无半条 |
| FR-007 知识库不注入 | 知识库问答的 prompt 不含记忆块标题 |
| FR-008~010 CRUD | 集成测试断言数据库行数与状态码 |
| FR-011 前端页面 | store 测试 + 浏览器实测 |
| FR-012 立即生效 | 增删改后下一轮 SystemMessage 变化 |

> FR-006 的「不截断」是可判定的：断言注入块中**最后一条**与源数据某条**完全相等**，
> 而不是前缀相等 —— 这样"截断"与"跳过"能被区分开。

## 与宪法的对齐核对

| 条款 | 满足方式 |
|---|---|
| I 简单优先 | 零新依赖；不向量化、不分类、不冲突消解；SPI 有同构先例 |
| II 边界即安全 | 模型只有「写」没有「删」；记忆只经显式工具写入 |

| IV 数据可追溯 | 唯一迁移 V9，只建一张表 |
| V 可验证 | 关键 SC 都断言到「送给模型的 SystemMessage」，不看模型回答 |
