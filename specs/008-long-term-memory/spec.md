# Feature Specification: 阶段 8 — 长期记忆

**Feature Branch**: `008-long-term-memory`

**Created**: 2026-10-25

**Status**: Draft

**Input**: 用户需求：「按照建议的几个缺口，帮我逐个实现」的第二项 —— README 承诺「可持久化的会话记忆」，
而 `memory` 包至今只有 `package-info.java`，长期记忆并不存在。

## 背景：现有的「记忆」只是短期记忆

阶段 1 的 `JpaChatMemory` 解决的是**一个会话内部**的上下文：换个会话，前面说过的话就没了；
新开会话谈同一件事，助手对你的偏好、身份、长期约束一无所知。

本阶段补的是**跨会话**的那一层：用户明确要求记住的信息，进入一张独立的表，并在**每一次**对话中
作为系统提示的一部分生效。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 让助手记住（Priority: P1）

作为用户，我希望在对话里说「记住：我的周报每周五下午交」，之后**新开一个会话**时助手仍然知道这件事。

**Why this priority**：这是「长期记忆」四个字的全部含义。没有跨会话生效，就只是又一张没人用的表。

**Independent Test**：在一个会话里让助手保存一条记忆；新建另一个会话并提问相关内容；检查送给模型
的上下文里确实包含这条记忆（用桩模型断言 SystemMessage 内容，而不是看模型回答猜）。

**Acceptance Scenarios**：

1. **Given** 用户明确要求记住某件事，**When** 助手调用保存记忆的工具，**Then** 该条记忆落库，且助手在回复里**明确告知**已记住（不能静默写入）。
2. **Given** 已存在若干条记忆，**When** 发起新会话的任意一轮对话，**Then** 送给模型的系统提示中包含记忆块，且每条记忆的原文在块内。
3. **Given** 一条记忆都没有，**When** 发起对话，**Then** 系统提示与阶段 1 完全一致（不出现空的「记忆：」标题）。
4. **Given** 同一件事被要求记住两次，**When** 第二次保存相同内容，**Then** 不产生重复条目（幂等）。

---

### User Story 2 - 自己管理记忆（Priority: P2）

作为用户，我希望在界面上看到助手到底记住了什么，并能改错、删掉过时的信息 ——
否则我无法信任这个功能，也不敢放它长期运行。

**Why this priority**：注入是**全局生效**的，一条错误记忆会污染之后所有对话。可见与可改是可信度的前提；
但即便没有界面，US-1 的注入价值仍然成立。

**Independent Test**：打开记忆页，看到已有条目；新增一条、把一条改成新内容、删掉一条；每一步都反映在列表与数据库里。

**Acceptance Scenarios**：

1. **Given** 已有多条记忆，**When** 打开记忆页，**Then** 按最近更新倒序显示全部条目，每条显示内容与更新时间。
2. **Given** 记忆页打开，**When** 新增一条记忆，**Then** 列表出现该条，且它立即参与下一轮对话的注入。
3. **Given** 存在一条记忆，**When** 编辑其内容并保存，**Then** 再次对话时注入的是新内容。
4. **Given** 存在一条记忆，**When** 删除它，**Then** 列表与后续注入都不再包含它。
5. **Given** 一条记忆都不存在，**When** 打开记忆页，**Then** 显示空状态提示，而不是错误或空白。

---

### Edge Cases

| 输入 / 场景 | 期望行为 |
|---|---|
| 记忆内容为空或全空白 | 拒绝，`40000`「记忆内容不能为空」 |
| 记忆内容超长（> 2000 字符，去空白后计算） | 拒绝，`40000`「记忆内容长度不能超过 2000」 |
| 内容与已有记忆**完全相同**（去空白后） | 不新增，返回已有那条（幂等），HTTP 200 |
| 记忆条数超过注入上限 | 只注入最近更新的 N 条，**不报错**；界面仍显示全部 |
| 单条记忆很长导致注入总量超上限 | 按倒序累加，超出预算即停止；**不截断半条记忆**（截断会产生语义残缺的约束） |
| 编辑/删除不存在的记忆 | `40004 资源不存在` |
| 记忆标识格式非法 | `40000`，**在查库之前**拒绝 |
| 用户只是随口说「记一下」但未明确要求长期保存 | 模型不应调用保存工具（工具描述中明确约束；此为提示工程约束，不作为自动化断言） |
| 助手在一次回复里连续保存多条 | 允许；每条独立校验与去重 |
| 知识库问答（单轮、无会话） | **不注入**长期记忆 —— 该链路要求「只依据给定资料作答」，注入个人偏好会干扰引用 |

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：系统 MUST 提供「显式保存记忆」的 Agent 工具，且工具描述 MUST 要求仅在用户明确要求记住时调用。
- **FR-002**：保存成功后，助手 MUST 在回复中告知用户已记住（不允许静默写入）。
- **FR-003**：记忆内容 MUST 在落库前去除首尾空白；去除后为空 MUST 拒绝；长度上限 2000（按归一后计算）。
- **FR-004**：内容与既有记忆完全相同（归一后逐字符相等）时 MUST NOT 新增条目，MUST 返回既有条目。
- **FR-005**：每次**会话内**对话的系统提示 MUST 追加记忆块（无记忆时不追加任何内容）。
- **FR-006**：记忆块 MUST 有注入预算：最多 30 条、累计不超过 6000 字符；超出时按「最近更新」倒序取舍，MUST NOT 截断单条记忆。
- **FR-007**：知识库问答链路 MUST NOT 注入长期记忆。
- **FR-008**：系统 MUST 提供记忆的列表、新增、编辑、删除接口（本地单用户，无权限概念）。
- **FR-009**：列表 MUST 按最近更新倒序返回全部条目（不受注入预算影响）。
- **FR-010**：编辑与删除不存在的记忆 MUST 返回「资源不存在」；记忆标识格式非法 MUST 在查库前拒绝。
- **FR-011**：前端 MUST 提供记忆管理页面，支持查看、新增、编辑、删除，且空列表有明确空状态。
- **FR-012**：记忆的增删改 MUST 立即影响下一轮对话的注入（不缓存、不需要重启）。

### Key Entities

- **Memory（新表 `memory`）**：
  - `id`（uuid，主键）
  - `content`（text，归一后 ≤ 2000）
  - `created_at` / `updated_at`（timestamptz）
  - 无分类、无标签、无向量 —— 见 research R-02 / R-03

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：让助手保存一条记忆后，新建会话发起对话，桩模型收到的 SystemMessage 中 100% 包含该条原文。
- **SC-002**：保存 35 条记忆后，桩模型收到的记忆块恰好包含 30 条，且为最近更新的 30 条（按 `updated_at` 断言）。
- **SC-003**：重复保存同一内容 3 次，表中只有 1 行。
- **SC-004**：记忆为空时，系统提示与阶段 1 逐字符相同（无残留标题或空行）。
- **SC-005**：无记忆时打开记忆页，显示空状态且无控制台错误。
- **SC-006**：删除一条记忆后，下一轮对话的 SystemMessage 中不再出现该条原文。

## Assumptions

- **显式写入，不自动归纳**：用户已选定该范式。理由是自动归纳会写入大量噪声记忆且用户不知道记了什么，
  与「可解释」冲突。代价：用户必须明确说「记住」，助手不会自己发现值得记的事。
- **不做向量检索**：记忆总量预期在几十条量级，全量注入（带预算）足够；引入向量检索只是把
  「取最近 N 条」换成「取最相似 N 条」，对几十条数据没有可观测收益（宪法原则 I）。
- **单一内容字段，不做分类/标签**：分类的价值在于按类别注入或检索，本阶段两者都不做。
- **不做记忆冲突消解**：新记忆与旧记忆矛盾时（如「我住在南京」与「我住在扬州」），系统不做判断，
  由用户在界面上删除过时的那条。自动消解需要语义判断，风险高于收益。
- **注入只发生在会话对话**：知识库问答是「只依据资料」的封闭链路（阶段 3 既定设计），不注入。
- `ai` 包本阶段**不动**：跨模块 AI 基础设施已在 `common/ai`，搬家属于大规模重构，不在本阶段范围。

## 明确不含（Explicitly Out of Scope）

| 不做的事 | 依据 |
|---|---|
| 自动从对话中归纳记忆 | 用户已选定「显式写入」范式；噪声与不可解释 |
| 记忆向量化 / 语义检索 | 几十条数据用全量注入即可（research R-03） |
| 记忆分类、标签、来源会话溯源 | 无消费方；将来要按类别注入时才需要 |
| Agent 侧删除/修改记忆的工具 | 破坏性操作只允许人在界面上发起（宪法原则 II 的延伸） |
| 记忆冲突消解、时效衰减、过期自动清理 | 需要语义判断；由用户手动管理 |
| 多用户 / 记忆隔离 / 权限 | 第一版本地单用户（宪法原则 II） |
