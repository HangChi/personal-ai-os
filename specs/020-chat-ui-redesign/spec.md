# Feature Specification: 对话页 UI 重设计

**Feature Branch**: `020-chat-ui-redesign`（从 main）

**Created**: 2026-10-26

**Status**: Approved

**Input**: 用户反馈「对话部分的 UI 非常丑」。经方案对比（设计稿见交付记录），确认按现代 AI 对话产品形态全量重做：全高列布局、助手消息去气泡、用户消息主色气泡、代码块带头部、流式打字圆点、输入区工具行、会话列表视觉清理。

## 现状问题（2026-10-26 真机截图走查）

1. **布局断裂**：消息区固定 52vh，其下经空白才到输入框——对话页不像对话，像卡片展览；窄屏更明显
2. **消息粗糙**：助手消息灰盒 + 顶部挤一行「角色 · 时间」小字；用户消息浅蓝盒；头像用 margin-top  Hack 对齐；复制按钮常隐（opacity 0），界面像死的
3. **Markdown 裸奔**：列表用浏览器默认大圆点；代码块无语言标识、复制按钮悬浮在代码上会遮挡；表格/引用块无设计
4. **输入区割裂**：知识库开关像补丁贴在输入框上方； Enter 行为无提示
5. **流式无生命感**：等待首 token 只有虚线框，无打字指示
6. **会话列表拥挤**：11px 灰字、hover 才出操作、无视觉节奏
7. **空态苍白**：无消息时只有一行 el-empty 文字，无引导

## User Scenarios & Testing

### User Story 1 - 全高对话列布局 (Priority: P1)

作为用户，打开对话页看到的是撑满可用高度的对话列：消息区自适应滚动，输入区停靠底部，不再有断裂的空白带。

**Independent Test**: 1440×900 与 375×800 两种视口下，消息区滚动、输入区始终可见停靠；页面本身不产生双滚动条。

**Acceptance Scenarios**:
1. **Given** 任意会话, **When** 打开对话页, **Then** 主区为全高列（= 视口高 − 骨架 136px），消息区 flex 撑满并可独立滚动
2. **Given** 消息很少, **When** 查看, **Then** 输入区仍停靠底部（不随消息上浮）
3. **Given** 375px 窄屏, **When** 查看, **Then** 布局退化为单列且无横向溢出

### User Story 2 - 消息视觉重做 (Priority: P1)

作为用户，我能一眼区分我和助手：助手消息带头像、直接排版（不套灰盒），操作（复制/时间）悬停才现；我的消息是右侧主色气泡。

**Acceptance Scenarios**:
1. **Given** 一条助手消息, **When** 渲染, **Then** 头像 + 内容直接排在卡面上，无包裹气泡；悬停出现复制与时间
2. **Given** 一条用户消息, **When** 渲染, **Then** 右对齐主色气泡，宽度自适应（最长 75%）
3. **Given** 流式输出中, **When** 首 token 未到, **Then** 显示三点打字动画（检索中时附文字状态）
4. **Given** 流式输出中, **When** 内容到达, **Then** 尾部光标闪烁，自动滚底

### User Story 3 - Markdown 与代码块 (Priority: P2)

作为用户，助手回复里的列表、代码块、表格有统一精致的排版；代码块带语言标识头部和一键复制。

**Acceptance Scenarios**:
1. **Given** 回复含代码块, **When** 渲染, **Then** 代码块顶部有语言名 + 复制按钮的头部条，复制成功有反馈
2. **Given** 回复含列表, **When** 渲染, **Then** 列表标记为主色、行距舒适，不再是浏览器默认大圆点
3. **Given** 回复含表格/引用, **When** 渲染, **Then** 表格有头底纹与边框、引用块有左侧色条

### User Story 4 - 输入区工具行与空态引导 (Priority: P2)

作为用户，知识库增强开关、检索条数、Enter 行为提示收进输入区上方的工具行；空会话时看到欢迎语和可点击的问题建议。

**Acceptance Scenarios**:
1. **Given** 输入区, **When** 查看, **Then** 工具行含：知识库增强 chip（开时带条数）、Enter 行为提示 chip
2. **Given** 空会话, **When** 打开, **Then** 显示欢迎语 + ≥3 个建议问题 chip，点击填入输入框
3. **Given** 流式中, **When** 查看输入区, **Then** 发送变为停止，工具行显示检索状态

### User Story 5 - 会话列表视觉清理 (Priority: P3)

作为用户，会话列表项有清晰的排版节奏：标题一行、元信息一行小字，当前会话有强指示，操作不抢眼但可发现。

**Acceptance Scenarios**:
1. **Given** 会话列表, **When** 查看, **Then** 当前会话有主色左边条 + 浅底；悬停出现操作
2. **Given** 分组, **When** 查看, **Then** 组标签更轻、与条目有间距

## Requirements

- **FR-001**: 对话主区 MUST 为全高列：`height: calc(100vh - 136px)`（实测骨架：header 60 + footer 60 + main 上距 16），消息区 flex:1 独立滚动，输入区停底
- **FR-002**: 助手消息 MUST 去气泡（头像 + 内容直排）；用户消息 MUST 右对齐主色气泡（max-width 75%）
- **FR-003**: 消息操作（复制 / 相对时间）MUST 悬停浮现，不常驻抢版面
- **FR-004**: 流式等待 MUST 有三点打字动画；首 token 后 MUST 为闪烁光标
- **FR-005**: 代码块 MUST 有头部条（语言名 + 复制按钮），复制成功按钮文字反馈
- **FR-006**: 列表 / 表格 / 引用 MUST 有统一样式（主色标记、头行底纹、左侧色条）
- **FR-007**: 输入区 MUST 有工具行：知识库 chip（含条数）、Enter 行为 chip；流式中发送按钮变停止
- **FR-008**: 空会话 MUST 展示欢迎语 + ≥3 个建议问题 chip（点击填入输入框）
- **FR-009**: 会话列表当前项 MUST 有主色左边条；操作悬停浮现
- **FR-010**: 全部新样式 MUST 走既有 `--os-*` 令牌与 EP 变量，亮/暗双主题都 MUST 验证
- **FR-011**: 既有功能 MUST 全保留：增强开关 / topK / 引用区 / 工具轨迹 / 待确认 / 重命名 / 删除 / 分组 / Enter 双模式

## Success Criteria

- **SC-001**: 1440×900 与 375×800 下对话页无双滚动条、输入区停靠、窄屏零横向溢出
- **SC-002**: 亮/暗 + 8 页回归零控制台报错（含新对话页）
- **SC-003**: 门禁：type-check 0 错、test:logic 全绿（≥348）、build 通过
- **SC-004**: 真机截图对比：新布局 / 消息两态 / 代码块 / 工具行 / 空态各一张存档

## 明确不含

- 不动后端（纯前端视觉）
- 不删用户历史会话数据（测试数据清理单独征求用户意见）
- 不改消息分页 / 虚拟滚动（数据量不需要）
- 不改侧栏整体（仅会话列表项视觉）
