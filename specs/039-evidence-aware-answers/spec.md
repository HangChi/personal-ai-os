# 039 · 按问题作答与来源分歧

**Feature Branch**: `go`（沿用当前工作分支）
**Created**: 2026-11-06
**Status**: Approved for implementation
**Input**: 保留可确认的答案，明确展示双方说法和具体分歧；Java 与 Go 同步，保留整体配色。

## User Scenarios & Testing

### User Story 1 - 有分歧也能获得有依据的部分（P1）

用户同时询问草稿、附件、晚到回复及测试步骤时，某一项有冲突不再阻止其他项作答。

**Independent Test**: 合成资料包含一个无争议规则和一对冲突规则；输出无争议结论与引用，以及双方原文和未决事项。

**Acceptance Scenarios**:
1. 部分冲突时保留全部相关证据；先输出经核对的可答项，再列出具体分歧。
2. 整个问题均有冲突时并列双方说法，不按相似度、排序或文风选边。
3. 用户请求人工测试时可给出明确标为建议的操作步骤；争议项不编造唯一通过标准。
4. 独立问答、知识增强对话与知识工具在两种后端采用一致规则；历史用于理解问题，不充当资料证据。

### User Story 2 - 分歧确实影响当前问题（P1）

**Independent Test**: 同一片段包含多个事实，旧冲突只涉及其中一个；询问另一事实不被旧冲突拦截。

**Acceptance Scenarios**:
1. 已记录的冲突重新核对与当前问题的关系；仅明确核对为无关时不纳入本次分歧，保留原治理记录。
2. 未核对、缺失或非法核对结果不能默认为“无冲突”。
3. 来源失效、版本变化及人工处理继续受原有约束。

### User Story 3 - 直接看懂来源分歧（P2）

**Independent Test**: 从来源按钮直接打开双方原文对照，键盘和窄屏均可操作。

**Acceptance Scenarios**:
1. 来源入口显示实际分歧数量；抽屉优先展示分歧原因、双方来源与原文。
2. 没有来源和异常说明时不展示空入口；检索过程保持折叠，分歧不在多个区域重复展示。
3. 流式、完成态及会话恢复的来源编号一致；现有配色不变。

### Edge Cases

伪造引文、越界编号、遗漏回答项、未覆盖冲突、模型超时/取消、证据不足、适用条件不同、空来源、重复来源、超长内容、旧接口调用方。

## Requirements

- **FR-001**: 逐项判断可答内容；所有事实必须有对应资料，未决分歧不能作为确定结论。
- **FR-002**: 生成结果须经过结构校验与独立语义核对；任一步失败降级为带具体原文对照的保护回答。
- **FR-003**: 无论生成是否成功，都不使用无关的通用“时间或制度版本”提示；仅提出与问题相关的澄清。
- **FR-004**: 来源编号由服务端统一产生；引用必须对应实际证据，来源文本按不可信引用处理。
- **FR-005**: 核对调用有时间和内容预算、无工具；不得因此触发业务操作、改变会话授权或跨会话混用证据。
- **FR-006**: 两种后端共享同一组关键契约用例，包含中英文与多字节字符边界。
- **FR-007**: 不修改数据库结构、真实资料、整体主题和迁移发布门禁。

### Key Entities

回答项：用户子问题、结论或建议、支持它的原文；分歧：同一事实的双方原文、原因和适用范围；核对结果：每项结论的支持情况与问题覆盖情况。

## Success Criteria

- **SC-001**: 部分冲突合成用例中，无争议项和双方分歧均可查到对应引用。
- **SC-002**: 所有伪造引用、无依据结论、漏核对和超时用例均不输出未核实的确定结论。
- **SC-003**: 无关的历史冲突用例正常回答，原冲突记录保持不变。
- **SC-004**: 两种后端契约用例结果一致，界面在桌面/窄屏、深浅主题下可读可操作。

## Assumptions

复用现有资料精审模型与队列、引用与来源抽屉；无新增依赖；使用隔离合成数据验证，不访问真实业务配置或数据。真实模型的语义判断不能保证绝对正确，需要保留原文与人工核对入口。
