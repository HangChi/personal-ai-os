# 规格：Go 全量后端迁移

## 用户要求与基线

用户明确要求在同一仓库创建名为 `go` 的分支，用 Go 覆盖当前 Java 实现；工作量过大时先交付文档，迁移范围不能遗漏现有实现。前端继续复用。

固定对照版本：`cb5d694d62fa93742b5789b97273e76d931ce335`。所有范围判断以该版本的源代码、SQL、配置与测试为准；历史 spec 描述与实际代码冲突时先记录差异，再根据实际行为确定兼容要求。

## 交付范围

### FR-001 全部业务能力

覆盖任务、会话/消息/流式对话、持久化 Agent 执行、提问与跟进队列、计划强制执行、工具审计、长期记忆、知识摄入/索引/RAG/治理、日程与提醒、MCP 双向接入、模型配置与探测、语音转写、附件、本地与 S3 存储、全局搜索、导入/导出。逐项来源见 feature-parity.md 与 inventory.json。

### FR-002 全部横向能力

保留统一信封与错误码、参数校验、错误脱敏、分页与排序、时区/时间格式、请求 ID、登录锁定、Cookie/CSRF、两层幂等、一次性确认、数据加密、共享会话、限流/并发协调、模型/工具执行预算、取消/超时、可观测性、保留清理、启动验证与优雅退出。

### FR-003 全部运行模式

覆盖 `combined/api/index/review/delivery` 五种角色、Worker 入口隔离、数据库租约与抢占、持久化事件、RabbitMQ 唤醒 Outbox 和轮询兜底、跨 API 实例提醒广播、Redis 的四类独立用途、OpenSearch 投影、Web Push 和 Webhook 投递。

### FR-004 前端兼容

前端页面/组件/样式默认复用。保持实际消费的路径、HTTP 状态码、JSON 字段与类型、状态枚举、请求头、Cookie、SSE 事件、文件上传/下载与错误行为。不得仅参考 docs/api.md；必须检查 frontend/src/api、types、stores、notifications、lib 和调用组件。

必要的客户端适配要逐项记录原因、范围与回归测试，不得以修改前端掩盖后端缺失。Java 与 Go 不要求互读 Spring 内部会话序列化，但切换时的重新登录行为必须显式说明并验证。

### FR-005 数据兼容

保留 42 个 Flyway 迁移脚本原文、历史顺序、表/列/索引/约束、现有 UUID 与序号、向量维度和索引操作符、加密字段、附件引用及导入/导出格式。不得改写已合并 SQL、让 ORM 自动建表或直接用空库证明存量库升级成功。

复用 Java 作为初期迁移执行器是可接受的过渡方式；独立 Go 发布前必须有经空库与存量库验证的迁移执行流程。禁止 Go 在启动时未校验历史便重新执行 V1–V42。

### FR-006 可靠性与副作用

所有写入仍走显式业务服务与事务。模型/文档解析/远程调用不得占用长数据库事务。幂等键冲突、执行结果不确定、确认令牌失效、租约丢失、进程崩溃、队列重复/丢失、网络断开等路径必须有对应测试。

恢复不能重复执行未知结果的外部写操作。`TOOL` 来源的过期执行占位不能按普通 HTTP 幂等占位的策略清理并盲重试。页面断开不等同于停止持久化任务；显式停止、排队与引导各有独立语义。

### FR-007 测试可追溯

154 个 Java 测试文件和 1,119 个测试声明均纳入基线。逐个迁移其行为断言，可合并为 Go 表驱动测试或集成测试，但必须在 progress.json 标明来源与替代证据。测试辅助类、模拟模型/MCP 服务与测试资源也必须保留职责。

Java 的覆盖率门禁仍属于基线运行质量要求；不能用 Go 行覆盖率或相同测试数量替代行为对照。Go 门禁需包含 build、vet、race、单测、真实 PostgreSQL/pgvector 与可选基础设施集成、前端端到端和故障恢复。

### FR-008 部署与维护

适配 Docker/Compose/Caddy、独立角色端口、监控与指标、备份恢复、保留策略、启动/停止脚本和 RAG/Agent 评估。Java 专属 JVM 指标可记录为 Go 等效指标；业务指标名称、标签、意义和采集拓扑必须单独验收。

### FR-009 增量盘点

清单必须可重建并检验漂移。任何新增源文件、修改或删除不能静默遗漏。基线更新必须列出新旧文件与行为变化、更新对应任务与测试映射。阶段完成时执行 `check`，最终切换时执行 `check-complete`。

## 使用场景与验收

### US-1 保留现有使用体验

同一套前端分别连接 Java 与 Go 的隔离测试环境，执行全部操作；结果、错误、状态、通知和文件内容在约定的动态字段归一化后相符。不能只验收 GET，也必须验证写入、副作用、冲突与权限失败。

### US-2 保留个人历史数据

将基线数据库和附件备份恢复到隔离环境，启动 Go 后检查历史任务/记忆/对话/引用/计划/运行记录/模型配置/知识来源/提醒，执行新增与更新，再验证导出和空库导入。不得读取生产密钥或写入当前运行实例进行试验。

### US-3 进程或依赖失败后继续使用

在模型流式输出、确认执行、索引提交、消息确认、搜索投影、推送/Webhook 投递中注入失败并重启，验证无重复副作用、无丢失已提交状态、租约失效的旧 Worker 无法覆盖新结果，前端重连只追赶事件。

## 完成定义

必须同时满足：

1. 固定基线覆盖项全部经审查并成为 `verified`，且证据路径存在。
2. 104 个注解路由、框架端点、27 个工具、调度/装配、配置、SQL 与所有业务分支均有迁移证据。
3. 每个 Java 测试声明都有替代验证；动态、随机和时间相关差异有明确归一化规则。
4. 真实数据库及可选基础设施模式回归通过；基础设施关闭/故障模式也通过。
5. 前端全量端到端、存量数据升级/恢复、故障恢复、部署切换验收通过。
6. `check-complete` 成功，且有人审查行为证据。脚本成功本身不能替代验收。
7. 备份、回退边界和部署文档齐备；回退不能撤销已执行的外部副作用，必须如实说明。

## 不属于本次重构的新增需求

不顺便改前端设计、不引入业务微服务、不更换数据库、不增设多租户/支付/权限体系、不删减少用的功能、不把 Java 类名逐字翻译为多余 Go 抽象。暂未实现的功能保持未完成状态，不用 stub、固定成功响应或文档勾选代替实现。
