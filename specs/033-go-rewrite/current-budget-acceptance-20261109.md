# 当前预算验收拆分 · 2026-11-09

## 修改内容

用户要求修正预算验收。新的当前套件将旧G4“最低预算下提交长的当前输入也必须成功”拆成两个独立必过场景：

1. **历史过长时成功裁剪**：先通过真实HTTP流完成六轮对话，再降低预算；短的当前输入必须完成，且实际模型请求是按原顺序保留的历史后缀、包含完整当前输入。请求中的历史确实减少；数据库中的12条既有消息逐字段不变，新增当前轮后共14条。
2. **当前输入自身超限时拒绝**：保留原重复120次的长输入，必须返回41301，没有done或delta、没有任何模型调用；数据库保留完整当前输入和一条中断回执，不伪造回答。

每项结束均恢复测试预算32768并撤销自己的请求观察器。新单测反向验证：即使返回41301，只要实际访问了模型或修改了原输入，验收仍失败；历史准备未完成也不算裁剪成功。

生产守卫、预算阈值、原E2E文件和历史报告没有修改。新增 `scripts/migration/current_budget_cases.py`，由隔离runner显式选择 `--mode acceptance` 或 `--mode budget`；默认原 `e2e` 模式继续保留冻结对照。其他83项用例对象、顺序、断言和观察模式原样继承。
