# Feature Specification: 安全自动化与资料互通

**Feature Branch**: `go`（沿用现有分支）
**Created**: 2026-11-06
**Status**: Implemented and verified（限定范围见 validation.md）
**Input**: 继续完成只读定时工作流、资料采集更新、日历互通和维护恢复中心；双版本对应实现，及时分批提交。

## User Scenarios & Testing

### User Story 1 - 可控的定时只读报告 (Priority: P1)
用户安排晨报、周报或资料巡检，按指定时区定时运行，查看结果、失败原因和重试记录，随时禁用。
**Why this priority**: 将已有数据转为定期行动提示，并保持自主执行的边界清晰。
**Independent Test**: 建立禁用的晨报，预览并手动运行；启用后到期仅产生一期，重复触发不重复执行，禁用后停止。
**Acceptance Scenarios**:
1. Given 有时区与本地时间，When 跨日或夏令时调度，Then 下一次运行按本地日历计算，重启后计划和历史保留。
2. Given 同一计划同时被多个执行器领取，When 到期，Then 每期仅一条有效运行，失败可以有界重试，历史可查询。
3. Given 只读任务，When 执行，Then 不修改任务/日程/资料、不发消息、不调用外部写工具；消费超过设定上限时停止并显示原因。

### User Story 2 - URL 资料采集和更新 (Priority: P1)
用户剪藏公开网页，查看规范来源和内容版本；再次导入相同内容不重复建文档，来源更新可保留历史并重新索引。
**Why this priority**: 从一次上传转为可维护、可追溯的资料来源。
**Independent Test**: 同一 URL 连续导入两次，再更新页面导入；检查单一资料身份、去重结果和版本历史。
**Acceptance Scenarios**:
1. Given 指向本机、内网或云元数据地址，When 导入或重定向，Then 拒绝，不能访问内部网络。
2. Given 超大、超时或非支持类型响应，When 采集，Then 有界失败且不留下半成品；网页脚本不执行。
3. Given 同内容或并发导入，When 提交，Then 去重原子；新内容产生可追溯版本，旧版本可读取，索引沿用现有任务机制。

### User Story 3 - ICS 日历互通和冲突提示 (Priority: P1)
用户导入或导出 ICS，导入前预览和选择确认，重复导入不产生副本，查看重叠日程提醒。
**Why this priority**: 先提供开放文件互通，避免直接连接外部账户和未知写入。
**Independent Test**: 导出再预览导入，核对标题、换行、时区、全天和支持的重复规则；重复导入无新增；相邻时间不冲突、交叠时间显示冲突。
**Acceptance Scenarios**:
1. Given 不支持的重复或例外规则，When 预览，Then 明确指出不支持并拒绝整批，不能静默丢规则。
2. Given 多条导入其中一条非法，When 确认，Then 全部不写；来源 UID 稳定去重。
3. Given 时间冲突，When 查看日历窗口，Then 展示相互重叠的日程，保持既有日程不变。

### User Story 4 - 维护与恢复中心 (Priority: P1)
用户集中查看服务/Worker状态、失败任务和最近的备份校验，下载备份并验证文件可读性与引用完整性，按指引执行隔离恢复演练。
**Why this priority**: 把运维状态和安全恢复入口放到界面，减少命令行排查。
**Independent Test**: 在中心上传合法和破损备份，检查校验结果及记录；查看失联Worker和失败任务；验证不会覆盖当前业务数据。
**Acceptance Scenarios**:
1. Given 破损或引用缺失备份，When 校验，Then 明确失败并列出有界问题，不执行恢复。
2. Given Worker心跳过期或任务失败，When 刷新，Then 显示状态、最近时间和可定位入口。
3. Given 恢复演练，When 执行，Then 只在隔离目标运行；界面必须区分文件校验与实际恢复演练，不将前者显示为恢复成功。

### Edge Cases
- 单次计划停机错过多期只追赶一次，下一期取未来时间，避免恢复后堆积调用。
- 超时运行不能以旧租约覆盖新结果；手动重试有消费上限和并发保护。
- URL 有片段、默认端口、不同大小写或 DNS/重定向变化时仍须规范化、防内部地址访问；不接受登录态、Cookie或任意请求头。
- ICS 只支持可无损映射的规则；不识别邀请收件人、不发送会议邀请。
- 所有列表和文件处理有明确上限，截断需可见；错误不泄漏凭据或内部路径。

## Requirements
### Functional Requirements
- **FR-001**: 支持只读晨报、周报、资料巡检，定时/手动运行、禁用、重试和运行历史；报告标明数据范围与截断。
- **FR-002**: 时区、执行时间、每日运行次数和每次消费/输出均受控；持久化一期身份和失败原因。
- **FR-003**: URL 采集支持公开 HTTP(S) 文本/HTML、去重、版本及来源追溯；全链路网络、文件大小和时间受限。
- **FR-004**: 资料更新使用既有解析/索引能力，版本内容与当前文档更新原子；无内容变化不重建。
- **FR-005**: ICS 支持预览后确认、原子导入、稳定 UID 去重和导出；不支持的语义明确拒绝。
- **FR-006**: 时间冲突按半开区间计算，重复实例参与；结果有界且不自动改期。
- **FR-007**: 维护中心聚合备份/校验、Worker、失败任务；文件校验只读业务数据并留校验记录。
- **FR-008**: 提供隔离恢复演练命令和报告导入/展示能力，禁止从页面直接覆盖当前运行数据库。
- **FR-009**: 双版本提供相同用户契约和行为；每项完成后验证并提交，不修改旧迁移、原验收门禁或运行环境。
### Key Entities
- Workflow：报告类型、时区、执行时间、启停、消费限制和下次执行。
- Workflow execution：期次、持久执行关联、状态、报告、失败原因、重试及消费。
- Source/version：规范来源、文档身份、内容摘要、版本内容、采集时间。
- Calendar exchange：稳定来源身份、日程映射与校验预览。
- Maintenance check：校验时间、文件摘要、计数、问题和演练报告。

## Success Criteria
- **SC-001**: 相同计划的同一期并发触发只产生一次有效执行；禁用后不产生新的自动执行。
- **SC-002**: 相同 URL 内容重复导入不新增资料或版本；内容变化后历史版本仍可读取。
- **SC-003**: 日历导出再导入保留支持字段，重复导入零副本；无效文件零部分写入。
- **SC-004**: 校验和演练不修改当前业务数据；清楚区分可读校验与实际恢复通过。
- **SC-005**: 四项主要流程均有实际双端测试与界面验证记录，分批提交可独立审阅。

## Assumptions
- 延续本地单用户使用方式和已有认证，不部署、不重启用户服务。
- 首版不含目录/RSS同步、外部日历账户同步、任意代码工作流或对外自动消息。
- 非交互工作流默认使用受限的只读报告策略；不授予任何写工具或凭据。
