# Feature Specification: 阶段 13 — 日历月视图

**Feature Branch**: `013-calendar-month-view`

**Created**: 2026-10-25

**Status**: Draft

**Input**: 用户需求：「继续剩余的内容」—— 日程模块只有列表，没有可视化日历。

## 背景

日程页现在是「新建表单 + 按天分组的长列表」。列表能回答「某天有什么」，
但回答不了「这个月紧不紧」「下周有没有空」—— 而这正是日程工具最常见的用法。

同时要修一个已经存在的缺陷：列表按天分组用的是
`occurrence.startsAt.slice(0, 10)`，取的是 **UTC 日期**。
在东八区，任何本地时间 08:00 之前的日程（对应 UTC 前一天）都会被分到前一天，
晚上 20:00 之后的则本来就在同一天 —— 于是同一份数据在列表里会出现
「标题写着明早 7 点，却排在今天下面」。

月视图会把这个问题放大成整格错位，所以必须先修。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 看整月安排（Priority: P1）

作为用户，我希望切到月视图后看到当月网格，每天格子里列出当天的日程标题，
点一条能打开编辑，点某天的空白处能新建到那天。

**Why this priority**：这是本阶段的全部价值。

**Independent Test**：造几条分布在本月不同日期的日程（含一条重复日程），
切到月视图，条目落在正确的格子里；点某格空白处新建，日期预填为那天。

**Acceptance Scenarios**：

1. **Given** 本月有日程，**When** 切到月视图，**Then** 显示 7 列 × 6 行的网格，
   今天所在的格子有视觉标记，非本月的日期灰显但仍占位。
2. **Given** 某天有 5 条日程，**When** 渲染该格，**Then** 最多显示 3 条，其余折叠为「还有 2 条」。
3. **Given** 一条重复日程在本月有 4 次发生，**When** 查看月视图，**Then** 4 个格子各出现一次，
   且带重复标记。
4. **Given** 用户在月视图点某一天的空白处，**When** 打开新建表单，**Then** 起始时间预填为该天（保持当前时刻的时:分或 9:00）。
5. **Given** 点击某条日程，**When** 打开编辑，**Then** 与列表视图点开的编辑行为完全一致。

---

### User Story 2 - 切换月份（Priority: P1）

作为用户，我希望用上一月/下一月/回到今天在月份之间移动，网格与数据同步更新。

**Independent Test**：连续点两次「下一月」，网格标题变成两个月后，且发出的查询区间是那个月。

**Acceptance Scenarios**：

1. **Given** 当前是 10 月，**When** 点「下一月」，**Then** 标题变为 11 月，格子里是 11 月的日程。
2. **Given** 已翻到别的月份，**When** 点「今天」，**Then** 回到当月且今天被高亮。
3. **Given** 切换月份，**When** 加载失败，**Then** 显示可读错误，网格保留骨架而不是整页空白。

---

### User Story 3 - 日期归属正确（Priority: P1）

作为用户，凌晨或深夜的日程必须落在**本地时间**对应的那一天。

**Why this priority**：这是既有缺陷，月视图会把它放大成整格错位。

**Acceptance Scenarios**：

1. **Given** 一条本地时间 2026-10-26 07:00（东八区）的日程，**When** 查看列表与月视图，
   **Then** 都落在 10-26 而不是 10-25。
2. **Given** 服务器返回的是 UTC 字符串，**When** 前端分组，**Then** 按浏览器本地时区换算日期。

## Edge Cases

| 输入 | 期望行为 |
|---|---|
| 某月 1 号是周日 | 网格从该 1 号开始，前面补上周一到周六的灰格（不越界到上上个月末） |
| 某月只有 28 天（2 月）且 1 号是周一 | 仍然渲染 6 行（多余整行灰格），避免切月时高度跳动 |
| 日程跨天（09:00 → 次日 10:00） | 显示在**起始日**，并在格子里标注跨天 |
| 全天日程 | 显示在最前，带「全天」标记 |
| 单月实例数超过一次查询上限 | 显示「另有 N 条未显示」提示，不静默少显示 |
| 时区为 UTC 的浏览器 | 分组结果与后端一致（换算为恒等） |

## Requirements *(mandatory)*

- **FR-001**：日程页 MUST 提供「列表 / 月」视图切换，默认保持列表（不改变现有用户习惯）。
- **FR-002**：月视图 MUST 渲染固定 7×6 网格（42 格），跨月日期灰显。
- **FR-003**：每格 MUST 最多显示 3 条，超出显示「还有 N 条」。
- **FR-004**：日期分组 MUST 按**浏览器本地时区**换算，MUST NOT 直接截取 UTC 字符串。
- **FR-005**：月视图 MUST 可点格空白处新建（日期预填）、点条目编辑。
- **FR-006**：切换月份 MUST 以该月首日 00:00 至次月首日 00:00（本地时区）为查询区间。
- **FR-007**：单月实例数超过本次加载条数时，MUST 明确提示还有多少未显示。
- **FR-008**：本阶段 MUST NOT 修改后端接口与数据库（复用现有 occurrences 查询）。
- **FR-009**：本阶段 MUST NOT 实现拖拽改期 —— 它需要 PATCH + 冲突处理 + 重复日程的「改本次还是改全部」语义，是独立问题。

## Success Criteria

- **SC-001**：`npm run test:logic` 全绿，新增测试覆盖「本地时区日期分组」「网格日期生成（含跨月补格）」
  「单月查询区间计算」三条纯逻辑。
- **SC-002**：`type-check` 与 `build` 通过。
- **SC-003**：真机（东八区）造一条本地 2026-10-26 07:00 的日程，列表与月视图都落在 10-26。
- **SC-004**：真机点「下一月」，网格与数据同步变化；点「今天」回到当月。

## Assumptions

- 不做周视图：月视图解决「看全局」，列表解决「看细节」，周视图夹在中间，
  信息密度与列表重叠而视野不如月视图 —— 加了只是多一个要维护的渲染分支。
- 月视图的数据与列表共用同一次查询结果（同一窗口），不做两套缓存。
  切视图会重新查询，代价是一个本地请求，换来「永远只有一个真相」。
