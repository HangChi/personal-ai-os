# 轮末后台任务与请求标识（P1 子集）

对应 Java ContextTaskConfig/MdcPropagatingExecutor 的尽力而为执行器：核心1、最大2、队列32、空闲60秒且核心也可退出。Submit 依次尝试核心执行单元、队列、最大并发；全满/已关闭时立即丢弃新任务并返回false。队列有界，队列满时新增执行单元可先执行新任务，这是原 ThreadPoolExecutor 的顺序，不保证严格全局FIFO。

只用于摘要/记忆沉淀等原本允许丢弃的轮末工作。持久化Chat Run、索引/投影/提醒投递不能使用此内存队列替代数据库恢复协议。

Go 不使用线程本地MDC。提交时只捕获经HTTP校验的 requestId，放到新任务context；不保留完整请求、Cookie、认证身份或HTTP截止时间。客户端结束不取消已接受后台工作。Stop 的执行器context取消会传给任务；未来涉及运行归属的任务必须显式传入经过验证的持久化身份，不能将诊断ID当作授权。

- Shutdown 停止接收并排空已接受任务，Wait(ctx) 由调用方指定等待期限。
- Stop 取消运行任务、丢弃队列，幂等并返回本次清空队列数；Go不能强杀不遵守context的任务，Wait不假报完成。
- 每任务错误/panic脱敏记录请求ID，不打印原始值/堆栈、不重试，继续后续队列；panic隔离是Go后台goroutine需要的进程保护，不声称与Java线程终止机制完全一致。
- Stats 返回一致计数/并发/队列快照，不暴露闭包、参数或身份。构造不启动永久goroutine；空闲执行单元退出后可重新提交。

race测试覆盖原请求ID跨任务传播/无残留、默认排队/扩容/丢弃、排空与超时、Stop取消/清队列、错误/panic、空闲退场重启、1,000路提交和并发关闭；20轮重复测试通过。应用生命周期及实际摘要/记忆/流式调度调用点尚未接线，不能视为这些业务已迁移。
